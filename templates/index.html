How it works

Three versions of the same idea, each fixing what the previous one got wrong.

2024, version 1: string matching

ChatterBot's "best match" returned the stored answer whose question looked most like yours, letter by letter. It missed anything worded differently.

2024, version 2: a fine-tuned language model

microsoft/DialoGPT-small (124M parameters) fine-tuned with Hugging Face Transformers and PyTorch. A bug in the training data format meant it learned the vocabulary of PSU programs, not how to answer: the question and the answer were tokenized separately and lined up word by word, instead of being one sequence with the loss on the answer only.

2026, version 3: retrieval first, the model fixed and measured

Answers come from retrieval. Your question and the {{ data_summary.entries }} written questions are turned into embeddings with all-MiniLM-L6-v2, and the closest one wins, with the university's name removed first (it made unrelated questions look alike). Below a similarity of {{ threshold }}, the bot says it doesn't know instead of guessing. That cut-off was chosen on a separate dev set.

The fine-tuned model was retrained the right way: one sequence per pair, question, end marker, then answer, with the loss on the answer only{% if training %}.
