How it works

A learning project from November 2024 that covers the whole loop: build a small dataset, fine-tune a language model, save it, serve it behind a web UI, and deploy it.

Model

microsoft/DialoGPT-small, a 124M-parameter GPT-2 model, fine-tuned with Hugging Face Transformers and PyTorch on a laptop CPU.

Data

About 170 question–answer pairs written from PSU's program pages. A script added reworded and shortened variants of each one.

Training

AdamW (learning rate 2e-5) with a cosine schedule, effective batch size 16, up to 10 epochs, an 80/20 train/validation split, and early stopping on validation loss.

Serving

Django and gunicorn (1 worker, 4 threads) behind nginx, on a 1-vCPU, 2 GB server. Each answer is generated with:

Why the answers are weak

In training, the question and the answer were tokenized separately and lined up position by position. A causal language model needs them as one sequence (question, end marker, answer) with the loss computed only on the answer. So the model learned the vocabulary of PSU programs, but not how to answer the question asked.

Today I'd fix that format, and compare the result against a retrieval baseline that returns the closest of the 170 written answers. For a fixed FAQ like this one, retrieval is often the better tool.
